# 真实用户旅程场景测试（策略转型方案）

> 2026-09-01 起，ZeppBridge 测试重心从「模块级强度测试」转向「用户旅程场景测试」。
> 模块级压力测试（`crates/core/tests/*_stress.rs`、`cli|mcp/tests/runtime.rs`）保留为回归基座；
> 本文定义的是其上的一层。

## 为什么转策略

v2.0.0 的 CHANGELOG 就是一份真实生活故障清单，每一项修复都能还原成一个用户故事：

| 上游修复 | 背后的用户故事 |
| --- | --- |
| 登录不再错选区域 | 「界面显示已连接，同步说成功，但库里什么都没有」 |
| 整条流失败不再报成功 | 「显示一切正常，睡眠数据却少了一个月」 |
| 历史列表去 500 上限 | 「我把三年历史都拉下来了，应用里只看到 500 条」 |
| 补拉可自动跑完 | 「补几年的历史要每隔几分钟点一次按钮，点一个小时」 |
| 坏时间增量不再当 0 | 「一次运动的配速和分段全错，因为一条坏读数把后面的都挪了位」 |
| 认不出的睡眠阶段不再叫清醒 | 「应用替我断言我凌晨三点醒着，其实我睡着了」 |

共同点：**每个模块单独看都是对的，连起来在真实路径上断了。** 模块级测试抓不到这类缺陷，
所以主战场换成按用户旅程组织的场景测试。

## 场景矩阵

每个场景 = 用户的一句话 + 可执行测试。全部只用临时目录 + 合成 fixture，不联网。

| # | 用户的一句话 | 测试内容（复用真实写入路径 persist_fetched_record / replace_workout_series） | 抓什么 |
| --- | --- | --- | --- |
| S1 | 「装好 app 第一天」 | 空数据目录 → CLI `status`(退出码 3) → 播种当日数据 → `status`/`contract`/`export` → MCP 五工具读取 | 空库→有库的每个出口都一致；无一条路径把"没同步"说成"0 条" |
| S2 | 「把三年历史一次补齐」 | plan_backfill 36 个月 × 6 流，混合 empty/failed/persisted，模拟"自动跑完"循环直到 complete；随后分页遍历全部 workouts（含 >500 条） | 断点续传、零推进自停、分页无重复/无漏行、计数一致 |
| S3 | 「同步到一半我把电脑合上了」 | 写入中途强杀连接（drop + WAL 残留）→ open_resilient 重入 → 数据不丢不重；迁移中 user_version 拨回 → 重入 | WAL 恢复、迁移重入、备份先行；进程死亡后锁自动释放 |
| S4 | 「出差两周没戴表」 | 15 天空档 + 3 天每天只有 12 个样本 → coverage 的 empty_from_cloud 与 failed 分开 → 导出 JSON/CSV/GPX | 空档期绝不出现 0 值/插值；"样本少的峰值"与"全天峰值"分开；账本完整性与曲线点数一致 |
| S5 | 「把数据交给 AI」 | 同一数据集 JSON/CSV/GPX 三格式 × 重复导出 + MCP 双协议（2024-11-05 握手与 2026-07-28 无握手）全部工具过一遍 | 格式间语义一致、缺失值语义不漂、MCP 只读且双时代都答得上 |
| S6 | 「换一台电脑」 | 数据目录 A 备份 → `ZEPPBRIDGE_DATA_DIR` 指到目录 B 恢复 → 再备份 → 校验；相对路径被拒；`ZEPPBRIDGE_CREDENTIAL_STORE=file` 0600 | 迁移后行数/覆盖一致；凭据落点由显式选择决定而非静默回落 |
| S7 | 「同步到底诚不诚实」 | 流级失败聚合（心率成功、睡眠失败 → 整体必须 Partial）；区域"猜的"要在状态里说出来；取消立即生效 | 任何失败路径都不能显示"已更新"；部分完成必须点名流 |

## 落地形态与运行方式

- **位置**：`crates/core/tests/scenario_*.rs`（S1–S4、S6、S7 的核心逻辑都在 core 公开 API 上）+
  `crates/cli/tests/scenario_*.rs`（S1/S5 的 CLI+MCP 出口）。
- **日常级**：每个场景一个缩减版（少量月份/天数/轮次），默认 `cargo test` 即跑，CI 全绿。
- **压力级**：`#[ignore]` 放大版（36 个月、千级 workout、50 轮往返），命令：
  - `cargo test --manifest-path src-tauri/Cargo.toml -p zeppbridge-core -- --ignored --nocapture`
- **CI**：沿用 `.github/workflows/stress-tests.yml`（日常级自动、压力级手动触发）。

## 纪律（与既有清单一致）

1. 缺失值绝不变成 0；真 0 与"没测到"必须区分。
2. 只用临时目录与合成 fixture；不碰真实用户数据目录。
3. 产品 bug **只记录**到 `BUGS_FOUND.md`（含位置、现象、复现测试名），不在此改产品代码。
4. 不放宽断言、不删旧测试；已知产品 bug 的探针用 `#[ignore]` 隔离并注明原因。
5. 不使用真实 token / user id / HAR 原文 / cookie。
